# Minus Cards (No Thanks! Style Mobile Network Game) - Implementation Plan

## 1. 프로젝트 개요 (Overview)
3~4인의 가족 및 친구들이 스마트폰(모바일 웹/PWA, 카톡 링크 즉시 접속 및 홈 화면 앱 설치 지원)으로 어디서든(LTE/5G/Wi-Fi 무관) 접속하여 즐길 수 있는 온라인 네트워크 심리전 카드 게임입니다.

---

## 2. 확정된 게임 규칙 (Game Rules Specification)

### 2.1 카드 및 코인 구성
- **카드 (총 33장)**: 숫자 `3` ~ `35`까지 각 1장씩 존재.
  - **색상 테마 (4단계)**:
    - `3 ~ 9` (1자리): 에메랄드/시안 계열 (Fresh Cyan)
    - `10 ~ 19` (10자리): 골드/앰버 계열 (Royal Gold)
    - `20 ~ 29` (20자리): 바이올렛/퍼플 계열 (Mystic Purple)
    - `30 ~ 35` (30자리): 크림슨/루비 계열 (Danger Crimson - 고위험 숫자 강조)
  - **카드 디자인**: 상단 반쪽과 하단 반쪽 모두에 큼직하고 화려한 숫자가 표기되어, 카드를 세로/계단식으로 반씩 겹쳐 놓아도 모든 카드의 숫자가 명확히 보이도록 설계.
- **코인 (루비 칩)**:
  - 1인당 **11개**씩 기본 지급 (3~4인 모두 11개 동일 지급).
  - 붉은색 보석처럼 영롱하고 빛나는 입체적 UI 디자인 (CSS `linear-gradient` 및 하이라이트 활용, **성능 저하를 유발하는 `backdrop-filter: blur` 등은 일절 사용하지 않음**).

### 2.2 방 생성 및 게임 시작 (Host Settings)
- **인원 제한**: **3인 ~ 4인** 전용.
- **방장(서버 개설자) 설정 항목**:
  1. **제외할 카드 장수 선택**: `2장 ~ 9장` 중 선택 (게임 종료 전까지 완전 비공개, **게임 종료 결과 화면에서 제외되었던 카드 목록 공개**).
  2. **보유 코인 개수 공개 여부**: `공개 모드` / `비공개 모드` 선택 (방 입장 및 게임 시작 시 모든 플레이어에게 공지 배너 표시).
- **카톡 링크 공유**: 방 생성 시 4자리 방 코드와 함께 `?room=ABCD` 형태의 URL 생성 → **'링크 복사 / 카카오톡 공유'** 버튼으로 터치 한 번에 친구 초대.

### 2.3 선후공 및 순서 결정 (Dice Roll Phase)
- 모든 플레이어가 동시에 **주사위 2개(2D6)**를 굴림.
- 주사위 합이 높은 순서대로 **1번 ~ 4번 턴 순서**를 부여받음.
- **동점자 발생 시**: 동점자들만 자동으로 재굴림(Re-roll) 연출을 진행하여 모든 인원의 순위가 명확히 갈릴 때까지 반복.
- 순서가 확정되면 화면 좌석 배치(하단: 나, 좌/상/우: 다음 턴 순서대로 시계방향 배치)가 정렬되고, 덱의 맨 위 카드 1장이 뒤집히며 공개됨.

### 2.4 턴 진행 (Turn Mechanics)
- 현재 턴인 플레이어는 두 가지 선택지 중 하나를 수행:
  1. **패스 (코인 1개 내기 - "No Thanks!")**:
     - 내 보유 코인이 1개 이상일 때만 가능.
     - 보유 코인 1개를 중앙 카드 위에 올려놓고, **다음 순서의 플레이어에게 턴이 넘어감**.
  2. **카드 가져오기 (Take Card)**:
     - 중앙에 공개된 카드와 그 위에 쌓인 **모든 코인**을 가져옴.
     - **내 보유 코인이 0개라면 패스할 수 없으므로 강제로 카드를 가져와야 함** (UI에서 '코인 내기' 비활성화 및 강제 획득 안내).
     - 카드를 가져가면 덱에서 다음 카드 1장이 자동으로 뒤집혀 공개되며, **턴은 한 번 더 하지 않고 다음 순서의 플레이어에게 넘어감**.

### 2.5 게임 종료 및 승리 조건 (End Game & Scoring)
- 덱의 마지막 카드까지 누군가 가져가면 즉시 게임 종료.
- **점수 계산 공식**: `내 카드 숫자의 총합 - 내 보유 코인 개수`
  - **연속된 숫자 그룹화 규칙**: 연속된 숫자 카드(예: `11, 12, 13`)는 하나의 묶음으로 처리되어 **가장 작은 숫자(`11`) 하나만** 점수에 합산.
- **승자 결정**: 최종 점수가 **가장 낮은(작은) 사람**이 승리!
  - **동점자 처리**: 최종 점수가 같다면 **보유 코인이 더 많은 사람**이 승리.
- **결과 화면**: 최종 순위 발표 + **처음에 제외되었던 히든 카드(2~9장) 공개 연출**.

## 3. UI/UX 및 화면 레이아웃 설계 (Mobile Portrait Optimized)

### 3.1 3~4인 한눈에 보기 레이아웃 (Table Layout)
모바일 세로 화면(100dvh)에서 스크롤 없이 모든 플레이어의 카드와 중앙 테이블이 한눈에 보이도록 배치합니다:
- **3인 플레이 시**:
  - **하단 (Bottom)**: 나 (내 카드 겹침 영역 + 내 코인 + 액션 버튼)
  - **좌측 상단 (Left)**: 다음 순서 플레이어 (타원형/컴팩트 겹침 카드 영역)
  - **우측 상단 (Right)**: 다다음 순서 플레이어 (타원형/컴팩트 겹침 카드 영역)
- **4인 플레이 시**:
  - **하단 (Bottom)**: 나
  - **좌측 (Left)**: 2번째 순서 플레이어
  - **상단 (Top)**: 3번째 순서 플레이어
  - **우측 (Right)**: 4번째 순서 플레이어
- **중앙 (Center)**: 남은 덱 장수 표시 + 현재 공개된 카드 + 카드 위에 쌓인 루비 코인 더미 애니메이션.

### 3.2 카드 반겹침(Staggered Stack) UI
- 각 플레이어가 획득한 카드는 오름차순으로 자동 정렬되며, **연속된 숫자 묶음(Run)끼리 세로로 반씩 겹쳐서(Upper/Lower 반쪽 숫자가 모두 노출되도록)** 배치됩니다.
- 연속되지 않은 숫자는 옆 열(Column)에 새로운 스택으로 나란히 배치되어, 나와 상대방이 어떤 연속 숫자를 노리고 있는지 한눈에 파악할 수 있습니다.

### 3.3 감정 표현(이모지 스탬프) & Web Audio 사운드 이펙트
- **실시간 감정 표현**: 화면 우측 하단 퀵 버튼을 통해 `"헉! 😱"`, `"고마워! 😍"`, `"제발 먹어! 🙏"`, `"노 땡스! 😎"`, `"망했다 😭"` 등의 말풍선 이모지를 날릴 수 있으며, 모든 플레이어 화면에 즉시 팝업 및 효과음 재생.
- **Web Audio API 합성 사운드 (외부 무거운 오디오 파일 로딩 없이 즉각 반응)**:
  - 코인 던지는 찰랑거리는 금속/보석 사운드
  - 카드 뒤집기/가져오기 스냅 사운드
  - 주사위 굴림 효과음 및 동점 서스펜스 사운드
  - 감정 표현 팝업 효과음 및 승리 팡파레

## 4. 기술 아키텍처 및 네트워크 설계 (Architecture)

- **Frontend Stack**: React 19 + TypeScript + Vite + Tailwind CSS (성능 최적화를 위해 모든 카드/스택 컴포넌트 `React.memo`, `useMemo` 적용, `blur` 필터 배제).
- **Zero-Config Online Multiplayer (PeerJS / WebRTC Mesh + Cloud Broker)**:
  - 별도의 유료 백엔드 서버 구축이나 Wi-Fi 동일 네트워크 제약 없이, 모바일 데이터(LTE/5G) 환경에서도 즉시 P2P/릴레이 연결이 가능한 **PeerJS(WebRTC 데이터 채널)** 기반 Host-Client 아키텍처를 사용합니다.
  - 방장(Host)의 스마트폰이 권위 있는 게임 서버(Authoritative Host) 역할을 수행하여 방 코드(예: `MC-4829`)를 생성하고, 참가자(Client)들은 카카오톡 공유 링크(`https://.../?room=4829`)를 누르면 방 번호가 자동 입력되어 1초 만에 입장합니다.
- **모듈형 파일 구조 (700줄 제한 엄수)**:
  - 모든 파일은 단일 책임 원칙(SRP)에 따라 200~300줄 이내의 작고 명확한 모듈로 분리합니다.
  - `APP_MAP.md`에 모든 컴포넌트, 훅, 네트워크 프로토콜 인터페이스를 문서화하고 관리합니다.
